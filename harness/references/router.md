# Context Router（阶段化上下文路由）

## 1. 目的

做到哪一步，只加载这一步需要的材料。避免两种失败：上下文过载导致幻觉、上下文缺失导致重复解释。

## 2. 输入与输出

- 输入：`state.md` 的 `stage`、需求包已有文件、目标工程代码范围。
- 输出：本轮应读文件清单 + 本轮禁止读的文件 + 下一动作。

## 3. 判定流程

```text
读 state.md
  ├─ 无需求包 → 提示 harness init
  ├─ status = blocked → 只输出阻塞项与解除条件
  ├─ stage = requirement → 加载规则 + 00-requirement + 目标代码入口
  ├─ stage = design      → 加载 00 + 01 + 相关接口/数据定义
  ├─ stage = develop     → 加载 01 + 工程 rules + state
  ├─ stage = test        → 加载 00 的验收点 + 02
  ├─ stage = visual      → 加载 05-visual + 冻结参考 + 实现截图
  ├─ stage = review      → 加载实际 diff + 00 + 03
  ├─ stage = release     → 加载 04 + 回退相关文件
  └─ stage = accept      → 加载全部验收点与证据
```

## 4. 加载表

| 阶段 | 必读 | 可读 | 禁读 |
|---|---|---|---|
| 需求分析 | `rules/must.md`、`00-requirement.md` | 目标代码入口、现有同类实现 | 其他需求的包 |
| 方案设计 | `00`、`01-design.md` | 接口、数据模型、调用方 | `02-test.md`、`03-review.md` |
| 开发 | `01`、`rules/`、`state.md` | 目标文件、相关测试 | 其他需求结论 |
| 测试 | `00` 的验收点、`02-test.md` | 可执行测试、运行说明 | 开发过程自述 |
| 视觉验收 | `05-visual.md`、`visual/ref/`、`visual/shot/` | 浏览器自动化输出、控制台日志 | 开发过程自述 |
| 审查 | 实际 diff、`00`、`03-review.md` | 受影响文件全文 | 开发过程自述 |
| 发布准备 | `04-release.md` | 构建/部署说明、回退脚本 | 未确认的新需求 |
| 验收 | 全部验收点 | 证据文件 | — |

「禁读」是硬约束：测试与审查读到开发自述，独立性即失效。

## 5. 规模分档与路由

| 档 | 判定 | 路由 |
|---|---|---|
| S | 单文件、单点、无接口/数据变更 | 合并设计与开发，测试与审查精简为清单 |
| M | 2–5 文件或单接口变更 | 全阶段，文档可合并但验收点必须单列 |
| L | 跨模块、接口/数据变更、影响多方 | 全阶段 + 影响面清单 + 回退演练 |

分档由需求阶段判定，写入 `00-requirement.md` 头部；开发中档位升级需回写并通知人。

## 6. 续接流程（换人/换 agent）

```text
1. 读 state.md：阶段、进度、阻塞、已验证、下一步
2. 核对代码：下一步涉及的文件当前是否与 state 描述一致
3. 不一致 → 先更新 state，再继续
4. 一致 → 按 router 加载当前阶段材料，直接执行下一步
```

禁止：不读 state 就凭对话记忆继续；state 与代码不一致时按记忆执行。

## 7. 上下文预算

- 单轮加载不超过 3 份需求包文档 + 目标代码片段。
- 大文件只读相关区段，读前先定位符号。
- 需要跨阶段材料时，说明理由并在 state 记录「越阶段读取」。

# 设计记忆机制（我们的视觉约定）

## 1. 是什么

**设计记忆 = 我们自己定的视觉约定**，让下次做界面时不用重新猜。

| | 设计记忆 `harness/design/` | 域文件 `harness/domains/` |
|---|---|---|
| 内容 | **我们的**视觉约定（品牌 token / 字阶 / 间距 / 组件约定 / 已定决策） | **行业**基线（同行都怎么做） |
| 性质 | 个性 —— 只适用于我们 | 共性 —— 跨公司通用 |
| 回答 | 「我们长什么样、我们定过什么」 | 「这类东西行业怎么做」 |
| 证据锚 | token 文件路径 / 截图 sha1 / 决策原文 | 可公开引用的 URL 带章节 / 文件:行号 |

**同一个东西不许在两处各写一份** —— 两份互相矛盾的真相源比没有更糟。

## 2. 怎么用

```text
做界面 → 先查设计记忆（有我们定过的约定就照做）
       → 查不到就按 ui-design 的流程定方向
       → 定完的设计决策**沉淀回设计记忆**（带证据锚）
```

对应 `ui-design` 技能里的：存量优化时「品牌资产保留」、方向选定后「把这次选定的方向与理由沉淀进 `harness/design/`」。

## 3. 文件结构

```text
harness/design/
├── README.md          本文件（机制说明）
└── <产品名>.md         一个产品一份（五块：品牌 token / 字阶 / 间距节奏 / 组件约定 / 已定视觉决策）
```

```markdown
# 设计约定：<产品名>

## 品牌 token
| 角色 | 值 | 来源 |
|---|---|---|
| 背景 | #FAFAFA | src/styles/tokens.css:3 |
| 强调 | #2563EB | src/styles/tokens.css:8 |

## 字阶
| 角色 | 字号 / 字重 | 来源 |
|---|---|---|

## 间距节奏
| 层级 | 值 | 来源 |
|---|---|---|
| 区块间距 | 32px | |

## 组件约定
| 组件 | 约定 | 来源 |
|---|---|---|

## 已定视觉决策
| 决策 | 理由 | 日期 |
|---|---|---|
| 列表用表格不用卡片 | 骑手要在扫一眼里比价，卡片纵向太慢 | 2026-11-21 |
```

## 4. 硬约束

1. **一条约定一个证据锚** —— token 文件路径、截图 sha1、或决策原文。没有锚的是印象，不是约定。
2. **只记「定了的」** —— 试过又推翻的不记；推翻时**追加新行并写明推翻理由**，旧行保留（防「谁改的、为什么改」失忆）。
3. **改设计记忆要经人确认** —— 同记忆层的晋升原则：自动写入只进候选，人批才生效。
4. **不抄竞品的样式** —— 记的是**结构性决策**（信息怎么分层、操作放哪、默认值是什么），不是表面样式。竞品的视觉风格是它的品牌资产。

## 5. 与其他两处的关系

| 落在哪 | 放什么 | 谁改 |
|---|---|---|
| `harness/design/` | 视觉约定（token / 字阶 / 间距 / 组件 / 决策） | 人确认 |
| `harness/domains/` | 行业基线（同行怎么做） | 人确认 |
| `harness/memory/` | 一次性项目经验（踩过的坑、口径） | 三条件晋升 + 人确认 |

**判断归属**：这是「我们定的」→ design；这是「行业都这样」→ domains；这是「这次踩的坑」→ memory。

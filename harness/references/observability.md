# 本地日志对账（只读）

## 1. 边界

| 允许 | 禁止 |
|---|---|
| 读取工程内或用户提供的本地日志文件 | 连接数据库、缓存、远程服务 |
| 读取本地构建/运行输出 | 修改、删除、轮转日志 |
| 在需求包内写对账记录 | 把日志原文整段贴进文档 |
| 使用用户提供的复现步骤 | 写入任何密钥、令牌、个人数据 |

没有可用日志时，明确写「无日志可用」并给出补验条件，不得编造现象。

## 2. 对账链

```text
用户动作 → 本地请求/事件记录 → 本地服务日志 → 代码路径 → 状态确认
```

每一步都要能回答：这一步看到了什么、与预期差在哪、证据路径是什么。

## 3. 执行步骤

1. **固定现象**：一句话写清「做了什么、期望什么、实际什么」。
2. **缩小时间窗**：记录动作发生的大致时间，只取该窗口日志。
3. **聚合**：先按关键字与时间聚合，统计条数与模式，不逐行读全量。
4. **抽片段**：只取能证明判断的 5–20 行，保留时间戳与关键字段。
5. **关联代码**：用片段中的标识（路由、函数名、错误码）定位代码路径。
6. **给结论**：现象发生在哪一层；证据不足则列为 `BLOCKED`。
7. **回写**：把时间窗、关键字、片段路径、结论写进 `state.md` 的「已验证」。

## 4. 片段规范

```text
来源：<日志文件路径>
时间窗：2026-11-19 10:00:00–10:02:00
关键字：favorite / 500 / AC-03
片段：
<5–20 行，保留时间戳，脱敏后贴入>
结论：<一句话>
```

脱敏：用户标识、令牌、Cookie、手机号、邮箱一律替换为 `<redacted>`。

## 5. 常见判断

| 现象 | 先看 | 再看 |
|---|---|---|
| 点击无反应 | 前端是否有请求发出 | 是否有 JS 报错 |
| 请求有、结果不对 | 服务日志状态码与入参 | 代码分支与返回值 |
| 数据没变 | 写入路径是否执行 | 事务/条件是否命中 |
| 偶发 | 时间窗内失败次数与分布 | 并发、超时、重试 |

## 6. 无日志时的降级

1. 用最小复现脚本或单测复现；
2. 仍无法复现 → 记录 `BLOCKED`，写清需要什么日志、哪个时间窗、由谁提供；
3. 禁止用猜测填补证据。

## 7. 反模式

- 把日志整文件粘进需求包；
- 只看最后一行报错，不看上下文；
- 用「应该是缓存问题」代替证据；
- 为了让门禁通过而删除失败日志。

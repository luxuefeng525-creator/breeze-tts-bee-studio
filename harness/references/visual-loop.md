# 视觉验收环（V 环）

> 解决的问题：UI 需求靠多轮对话「看着像了」结案，轮次越多偏得越远。
> 原则：**参考先冻结、采集靠脚本、比对有清单、结论进证据。** 眼睛不是自由看，是固定视角地看。

## 1. 三道闸

```text
参考冻结 → 脚本采集 → 结构化比对 → V 门禁（人确认）
   ↑人确认                                   ↑缺证据即 FAIL
```

任一道缺失，不得进入审查阶段。

## 2. 参考冻结（开工前，人确认）

- 参考来源：原型 HTML / 设计稿导出图 / 竞品页面截图。来源必须写路径或 URL。
- 落盘位置：`requirements/<REQ>/visual/ref/`，文件名 `ref-<页面>-<状态>-<视口>.png`。
- 记录指纹：每个参考文件记 `sha1` 与获取时间，写进 `05-visual.md`。
- 参考一旦冻结，本轮需求内不得替换；要换 → 回需求阶段，重新确认。
- 只有文字描述、没有可视参考的 UI 需求 → `BLOCKED`，先补参考，不猜。

## 3. 脚本采集（可重放）

- 采集必须是可重复执行的命令，不允许「手动点几下截个图」。
- 输出目录：`requirements/<REQ>/visual/shot/`，文件名固定 `<page>-<state>-<w>x<h>.png`（如 `home-default-1440x900.png`）。
- 张数必须等于 `pages × states × viewports`；少一张、多一张、命名不符都判 FAIL。
- 每次采集同时产出：
  - 截图（PNG）；
  - DOM 快照或关键节点文本；
  - 控制台错误与失败请求列表。
- 视口：默认 `1440x900`、`768x1024`、`375x812`；项目已有约定则按项目，写进 `05-visual.md`。
- 状态：每个页面至少覆盖「默认 / 空 / 加载 / 错误 / 无权限」中相关的项，逐项截图。

## 4. 通道选择（硬边界）

| 场景 | 用什么 | 禁止 |
|---|---|---|
| Web / H5 / 小程序 H5 | 浏览器自动化（截图 + DOM + 网络） | 用 computer-use 代替 |
| 需要登录、扫码、验证码 | 人接手一次，保存登录态供脚本复用 | 把账号密码写进需求包 |
| 原生桌面 / 设计工具 / 无法脚本化的界面 | computer-use，人工在场，一次性 | 用它做回归与多轮比对 |
| 多轮迭代比对 | 只允许脚本化采集 | 每轮重新「看一眼」 |

结论：computer-use 是**兜底通道**，不是主通道。主通道必须可重放，否则每轮结论不可对账。

## 5. 结构化比对

逐项比对，每项给 `PASS / FAIL / BLOCKED`，不允许「整体感觉」：

| 维度 | 判定依据 |
|---|---|
| 布局 | 区块顺序、栅格、对齐、溢出 |
| 间距 | 关键间距与参考一致或有书面偏差说明 |
| 颜色 | 主色/背景/文字色的取值或截图取色 |
| 字号字重 | 标题、正文、辅助文字层级 |
| 组件状态 | hover / focus / disabled / 错误 / 空态 |
| 响应式 | 三个视口下无横向滚动、无遮挡 |
| 控制台 | 无报错、无失败请求 |

比对结果写 `05-visual.md`，每行带参考图与实现图的路径。

## 6. V 门禁

机读行，字段不可省：

```text
V: PASS | 参考: <ref 目录或 sha1> | 视口: 1440/768/375 | 状态: 5/5 | 截图: <shot 目录> | 确认人: <姓名> | 时间: YYYY-MM-DD HH:mm | 确认原文: "<原话>"
```

- 缺参考、缺视口、缺状态、缺截图路径、缺控制台结论 → `FAIL`。
- 截图张数不等于 `pages × states × viewports` → `FAIL`，并列出缺失文件名。
- agent 只能判 `FAIL` / `BLOCKED` / `待确认`；`PASS` 必须有人确认原文。
- 连续 3 轮比对不收敛 → `BLOCKED`，回需求或设计，禁止继续盲改。

## 7. 安全

- 只连本地或测试环境；生产地址一律不采。
- 截图与 DOM 快照不得含真实用户数据；有则打码后再落盘。
- 登录态文件不入库，不写进需求包。
